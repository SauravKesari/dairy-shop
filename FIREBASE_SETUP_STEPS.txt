DAIRY PARLOUR - FIREBASE SETUP STEPS
====================================

The app stores all data in Firebase (Firestore + Firebase Auth). There are no backend APIs to run.
Do the steps below once. Each Firebase project needs steps 1-4 and 6-8.


PART 1 - PUSH THE CODE AND OPEN THE PULL REQUEST
------------------------------------------------
The changes are committed locally on branch "feat/firebase-storage" (commit f3f587c)
but are not pushed yet, because this machine has no GitHub login.

1. Install the GitHub CLI:
     https://cli.github.com   (Ubuntu: sudo apt install gh)

2. Log in to GitHub:
     gh auth login

3. Push the branch:
     cd ~/Downloads/dairy-shop
     git push -u origin feat/firebase-storage

4. Open the pull request:
     gh pr create --base main --head feat/firebase-storage --title "Replace localStorage with Firebase (Firestore + Auth)"
   (Or open https://github.com/SauravKesari/dairy-shop and click "Compare & pull request".)

5. The project uses npm (package-lock.json). After pulling changes, run
   "npm install --legacy-peer-deps".


PART 2 - CREATE THE FIREBASE PROJECT (Firebase console)
-------------------------------------------------------
1. Go to https://console.firebase.google.com and click "Add project".
   Example name: dairy-shop-prod
   Also create a second project, for example dairy-shop-test, for trying things out and for
   the Go-Live acceptance test runner (it writes real bills).

2. Build -> Firestore Database -> Create database
     - Mode: Production mode
     - Location: asia-south1 (Mumbai)

3. Build -> Authentication -> Get started -> Sign-in method -> Email/Password -> Enable -> Save
   (Staff log in with mobile + PIN; the app turns the mobile number into a login email for you.)

4. Project settings (gear icon) -> General -> Your apps -> click the Web icon (</>)
     - Register the app (any nickname, for example "dairy-web")
     - Copy the firebaseConfig values shown. You need them in Part 3.


PART 3 - CONFIGURE THE APP ON YOUR COMPUTER
-------------------------------------------
1. Install dependencies:
     cd ~/Downloads/dairy-shop
     npm install --legacy-peer-deps
   (Plain "npm install" fails with an ERESOLVE error because of a TypeScript 7 conflict.)

2. Create the env file:
     cp .env.example .env.local

3. Open .env.local and fill in the values from Part 2, step 4:
     VITE_FIREBASE_API_KEY=...
     VITE_FIREBASE_AUTH_DOMAIN=...
     VITE_FIREBASE_PROJECT_ID=...
     VITE_FIREBASE_STORAGE_BUCKET=...
     VITE_FIREBASE_MESSAGING_SENDER_ID=...
     VITE_FIREBASE_APP_ID=...
     VITE_AUTH_EMAIL_DOMAIN=dairyshop.local   (don't change this after staff accounts exist)
     VITE_HISTORY_DAYS=90                     (days of bills/stock history loaded live)
     VITE_USE_EMULATOR=false

   .env.local is git-ignored. Never commit it.


PART 4 - DEPLOY THE SECURITY RULES (REQUIRED)
---------------------------------------------
The rules enforce owner/cashier permissions. Without them, Firestore refuses every request
(production mode).

1. Install the Firebase CLI and log in:
     npm install -g firebase-tools
     firebase login

2. Select your project:
     firebase use --add        (pick the project, give it the alias "default")

3. Deploy the rules:
     firebase deploy --only firestore:rules,firestore:indexes


PART 5 - FIRST RUN
------------------
1. Start the app:
     npm run dev
   Open http://localhost:3000

2. The "First-time setup" screen appears. Enter:
     - Shop name
     - Owner name
     - Owner mobile number
     - PIN (at least 6 digits)
   This creates the owner account. It only works once per Firebase project.

3. Settings -> fill in shop address, phone, UPI ID, invoice prefix, GST and so on -> Save.

4. Add your products:
     - Products -> CSV import (products + opening stock), or add them one by one
     - Customers with old udhaar -> CSV import of customer dues

   On the TEST project only: Settings -> "Load Demo Data" fills an empty shop with sample data.

5. Add cashiers:
     Users -> Add Cashier Staff -> name, mobile, PIN (at least 6 digits), role.
   Each cashier then signs in on the counter device with their own mobile + PIN.


PART 6 - HOSTING (OPTIONAL, FREE, HTTPS)
----------------------------------------
     npm run build
     firebase deploy --only hosting
   The app will be live at https://<project-id>.web.app
   Open that link on the shop phone/tablet and use "Add to Home Screen".
   A custom domain can be added in the Firebase console -> Hosting -> Add custom domain.

   Test site (dairy-shop-test project):
     - Put the test project's firebaseConfig values in .env.test.local (same keys as .env.local)
       and add VITE_SHOW_DEV_TOOLS=true. This shows the Deploy guide and the Go-Live test runner,
       which only appear on test builds.
     - Add the alias once:  firebase use --add   (pick dairy-shop-test, alias "test")
     - Deploy rules once:   firebase deploy --only firestore:rules,firestore:indexes -P test
     - Deploy the site:     npm run deploy:test
       Live at https://dairy-shop-test.web.app
     - Run "npm run build" again before any prod deploy, so dist/ holds the prod build.


PART 7 - DAY-TO-DAY NOTES
-------------------------
- Internet down:
    Viewing data still works from the device's cache, and expenses/payments queue and sync later.
    Bills need internet (to lock stock and get an invoice number). Write a numbered paper bill,
    then enter it later with "Paper Bill Entry" in POS.

- Staff forgot their PIN:
    Staff can change their own PIN: Users -> key icon on their own row.
    For someone else: Firebase console -> Authentication -> Users -> delete that login,
    then add the person again in the app's Users screen.
    (The free plan has no way for the owner to reset another person's PIN from the app.)

- Remove a cashier:
    Users -> power icon. A deactivated user is blocked by the security rules at once.

- Backups:
    Settings -> "Export Full Database" downloads a JSON backup. It contains products, customers,
    udhaar ledger, purchases and expenses, plus the last 90 days of bills, stock movements and audit logs.
    Do this daily, or set up scheduled Firestore exports
    (needs the Blaze pay-as-you-go plan; small shops normally stay within the free usage):
      gcloud firestore export gs://YOUR_BACKUP_BUCKET/$(date +%F)

- Free-tier limits (Spark plan): 50,000 reads and 20,000 writes per day, 1 GB stored.
    Keeping the POS tab open all day uses far fewer reads than reopening the app many times.


PART 8 - TEST LOCALLY WITHOUT A REAL PROJECT (OPTIONAL)
-------------------------------------------------------
1. Start the emulators (needs Java):
     firebase emulators:start --only firestore,auth --project demo-dairy

2. In .env.local set:
     VITE_FIREBASE_PROJECT_ID=demo-dairy
     VITE_FIREBASE_API_KEY=demo-key
     VITE_USE_EMULATOR=true

3. Run "npm run dev". The data lives only in the emulator and is wiped when it stops.
